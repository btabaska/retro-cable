# API spec

Split from `docs/plan.md` (approved Nov 1, 2026) without changing its meaning; plan text is copied verbatim. Where this spec and the plan disagree, this spec wins for its area. Related specs: `scheduler.md`, `catalog.md`, `web.md`, `ops.md`.

### Tuning in

- `GET /tune/{channel}` returns the current item, the offset in seconds and the next few items. The app starts the file at that offset; no server process runs per channel.
- Day schedules are cached and regenerated when the catalog or templates change.

### Access control

- Device pairing: the app shows a 6-digit code, you approve it in the admin (or Hermes asks you in chat), and the server issues a device token.
- Media URLs are HMAC-signed and expire in a few hours.
- App Store Connect keys live only in GitHub secrets. Homelab secrets live in a `.env` readable only by the deploy user.

## Telemetry

The server exports OpenTelemetry to Prometheus, Loki and Grafana; the app reports playback events to the server.

| Signal | Source | Used for |
| --- | --- | --- |
| Tune latency (tap → first frame) | App event | Alert if p95 exceeds 2 s |
| Stalls and playback errors, with file and offset | App event | Finds bad encodes for re-encoding |
| Schedule generation time, cache hits | API metrics | Catches slow catalogs |
| Missing-file skips per channel | Scheduler log | Gap report and archive to-do list |
| Request logs and errors | API logs → Loki | Debugging by agents |
| Disk, CPU, transcode queue | Node exporter, worker | Capacity and ingest progress |
| Watch history, likes, hour-of-week | App event | Station manager and pruning |

## Implemented (Phase 1)

- The API is FastAPI in `server/src/retro_cable/`. Behind Caddy it is served under `/api/*` with the prefix stripped, so `GET /api/health` reaches `/health`. The Vite dev and preview servers proxy the same way.
- `GET /health` returns `{"status": "ok"}`. Since M2 it returns 503 with `{"status": "data dir not writable"}` when the database, or the data folder it lives in, exists but the api can't write it (a host data dir owned by another uid), so the compose healthcheck, `up --wait` and `smoke.sh` fail and `deploy.sh` rolls back. A data folder that doesn't exist yet is fine.
- `GET /version` returns `{"version": "<x.y.z>", "commit": "<short sha>"}`. The version is `retro_cable.__version__`, bumped by Release Please; the commit comes from `RC_GIT_SHA` (baked into the image at build time, `dev` locally).
- Operation IDs are set explicitly (`getHealth`, `getVersion`) because the web and tvOS clients are generated from them.
- `server/openapi.json` is generated by `make api` and committed. It omits `info.version` so it only changes when the API does. A server test fails if the committed file is stale, and web CI fails if the generated client is stale.

## Implemented (Phases 3–4)

Times are ISO 8601 in the catalog time zone, with offset. `year` must be 1990–2010, or 0 for All Years (Nov 10 2026): the real date and time, every channel on the dial and every episode eligible (`scheduler.md`, All Years); a `date` then falls in the real year. `date` is `MM-DD`, defaulting to today, with Feb 29 falling back to Feb 28.

- `GET /channels?year&date` (`getChannels`) returns every channel with its identity on that date. Channels not yet launched have `on_air: false` and their `launch` date. The response also carries the simulated `now`, `weekday` and `timezone`.
- `GET /guide?year&date&start=HH:MM&hours` (`getGuide`) returns back-to-back slots for every channel on the dial, sorted by number, from `start` (default 00:00) for `hours` (default 24, max 36). Slots have `kind` (episode, movie, bumper or filler), start and end, title, season and episode, effective `air_date`, `new` and `transplant`, plus (Phase 7) `holiday` and `holiday_name`: the holiday the program is tagged for while that holiday is in force (see `scheduler.md`, Phase 7), or null. They carry no file paths. `/tune` slots carry the same fields.
- `GET /tune/{channel}?year&count` (`tune`) returns the slot airing at the simulated now, `offset_seconds` into it, and the next `count` slots (default 3). Each slot has a signed `media_url`, which is null for filler. A channel not on the dial returns 404.
- **Media URLs** are `/media/<path>?exp=<unix>&sig=<hmac-sha256(path, exp)>`, valid for 4 hours and signed with `RC_MEDIA_SECRET`. If the secret is unset, a random one is generated per process. `<path>` is the normalized MP4 when the item has one (`media_path`, see the catalog spec), otherwise a relative file already under the media root (demo feeds, fixtures); raw sources are never signed. In dev and under `vite preview`, the API serves `/media/*` itself, with byte ranges, after checking the signature. In the compose stack, the web container's Caddy serves `/media/*` from the read-only media mount, but only after `forward_auth` asks the API's `GET|HEAD /media-auth` (not in the OpenAPI spec). That endpoint checks the original URI that Caddy sends in `X-Forwarded-Uri` and answers 204, or 403 for a missing, tampered, retargeted or expired signature; Caddy hands the 403 to the client. Uvicorn runs with `--no-access-log` and the web Caddy has no access log, so signed URLs aren't logged; `local-test` fails if `sig=` appears in the stack logs. `web/e2e/media.spec.ts` checks 206 for a valid range and 403 for a tampered signature, a different path and an expired `exp`, both through Caddy (local-test) and through the API (CI).
- **Settings** come from the environment: `RC_CATALOG_DIR` (default: the repo `catalog/`), `RC_DB` (default `$RC_DATA_DIR/retro-cable.db`), `RC_MEDIA_DIR`, `RC_MEDIA_SECRET` and `RC_SEED`. The scheduler is rebuilt when a catalog file or the database changes. Database changes are detected with SQLite's `PRAGMA data_version` on one long-lived connection (plus the file's inode, so a replaced file is seen), not file mtimes: opening and closing connections moved the `-wal` mtime on plain reads, so every admin read rebuilt the scheduler and stalled the next TV request. Commits still in the WAL are seen. Rebuilds run under a lock, so concurrent requests after a change share one rebuild. Admin requests migrate the database once per file, not per request.
- **Demo data.** `make demo-db` writes long color-bar feeds into `.fixtures/_demo/` (11, 22, 44 and 90 minutes, plus a bumper) and seeds `data/demo.db`. Every carried show gets weekly episodes, 22 a season, pointing at the feed for its runtime class. Air dates are invented. Episodes take their feed's length, so the feeds are always full length: seeding refuses a feed shorter than its runtime class (10, 20, 40 and 80 minutes), because shrunken feeds made guides of tens of thousands of seconds-long programs. The test stack, Playwright's API (`tools/e2e-api.sh`) and CI all use the same full-length feeds; CI caches them. `make demo` runs the API on that database with the web dev server.

## Implemented (Phase 10: admin)

Admin routes live under `/admin/*` (`/api/admin/*` behind Caddy) and appear in `openapi.json` with the tag `admin`. They are LAN-only like everything else and have **no auth in M1**. Every write appends an overlay revision (see `catalog.md`, Phase 10) and refreshes the schedules at once, with no restart.

| Route | Operation | Does |
| --- | --- | --- |
| `GET /admin/channels` | `adminListChannels` | Every channel by number, with `custom` (editable) and a show count, plus `state` (revision, catalog version, can_undo) |
| `GET /admin/channels/{id}` | `adminGetChannel` | The channel as a `ChannelDraft` (YAML channels too, read-only), with each show's `premiere`, plus `shows[]`: per carried show its real `debut`, the `premiere` on this channel and where it is set (`premiere_source`: `admin` or `catalog`), the resulting `first_air` (S1E1) and `last_air` on this channel, `on_air_until` and `airs` |
| `PUT /admin/channels/{id}/premieres/{show}` | `adminSetPremiere` | Body `{premiere: date or null}`. Sets or clears the pretend premiere of one carried show on one channel, YAML or custom (M2). Inputs only: an undoable overlay revision; the guide follows on the next read. 404 when the channel doesn't carry the show; 409 with a `CheckResult` (field `premiere`) for a date outside 1990-01-01..2010-12-31, a date after the show leaves the channel, or clearing a premiere that is set in `synthetic.yaml`. Returns the updated row, warnings and `state` |
| `GET /admin/library?q=` | `adminLibrary` | Every show and movie in the database, plus (M4) titles a channel carries that the database doesn't know yet (0 episodes, no dates; a show with `part_of` counts the series seasons it airs as, and the series loses them, as the scheduler airs them), filtered by title. Uncarried items come first. Each has years, its real `debut` date (M2), playable episodes (what the schedule can air: normalized, or already under the media root with a runtime, and not shorter than half the expected runtime; raw `ingest scan` sources count once normalized), the channels carrying it, and (M4) the lineup's `tmdb_id` (`tv:N` / `movie:N`) and first-aired `year` from the effective overrides, for the rig's `ingest acquire`; (Nov 9 2026) `shifted`: the show airs on moved dates somewhere (a pretend premiere on any channel, or a US debut), so acquire keeps all its seasons |
| `POST /admin/check` | `adminCheck` | Runs the save checks on a draft without saving |
| `POST /admin/preview` | `adminPreview` | The checks plus a Sunday–Saturday week of the draft's guide for `year` (and `date`, default today), with the draft applied in memory only |
| `POST /admin/channels` | `adminCreateChannel` | Check, then save. Returns 409 with the `CheckResult` when the checks fail |
| `PUT /admin/channels/{id}` | `adminUpdateChannel` | Same, for a custom channel. Returns 403 for a YAML channel |
| `DELETE /admin/channels/{id}` | `adminDeleteChannel` | Removes a custom channel |
| `POST /admin/undo` | `adminUndo` | Reverts the last save or delete. Returns 409 when there is nothing to undo |
| `GET /admin/state` | `adminState` | Revision, catalog version and can_undo |
| `GET /admin/media/progress` | `adminMediaProgress` | How far the rig's conversion has got (M2): see below. 404 until the rig has written `progress.json` |
| `GET /admin/station/runs?limit=` | `adminStationRuns` | The weekly station manager's runs, newest first (M5; `limit` 1 to 100, default 20): `auto_apply` (`RC_STATION_AUTO_APPLY` on this server) and per run its id, `created_at`, `week_of`, `status` (`applied`, `proposed`, `dry_run`, `skipped`, `failed`), model, the `revision_id` it saved, a summary, the report (signals, changes, power hours, what was left out; `catalog.md`, M5) and `can_undo` (applied and still the head revision: `POST /admin/undo` reverts it) |

**Conversion progress** (`GET /admin/media/progress`, M2 B13) reads `progress.json` at the media root, which the rig's worker keeps current (`ingest/progress.py`, see `ops.md`):

```json
{
  "done": 1240, "total": 2000, "failed": 2,
  "encoder": "gpu | cpu | paused", "gpu_busy": true,
  "recent_seconds": [31.2, 29.8],
  "shows": [{ "title": "Dexter's Laboratory", "done": 38, "total": 52, "failed": 2, "state": "converting | queued | done" }]
}
```

`shows` is in conversion order; episodes are grouped per show, movies as one `Movies` row and bumpers as one `Bumpers` row. `done`, `total` and `failed` at the top are the sums. `total` counts items with a source file the worker can read; `failed` counts this pass's failures (retried on the next pass). `encoder` is `gpu` (NVENC) or `cpu` (x264) for the file in progress, and `paused` when the worker is between passes or hasn't written the file for 30 minutes (stopped); then no show is `converting`. `gpu_busy` is true when `--encoder auto` chose x264 because the GPU was in use. `recent_seconds` is the wall-clock time of the most recent finished files (newest last, up to 20; kept across worker restarts). A show is `done` when all its files are. No paths, hosts, URLs or tokens.

**Checks before save** each have a `field` (`number`, `call_sign`, `name`, `launch_year`, `shows`, `shows.<i>`, `shows.<i>.premiere` or null) and a plain-words message. Errors block saving:
- The name or call sign is empty, or the call sign is longer than 6 letters or digits.
- The number is outside 1–999, or is already used by another channel's identity on any date the new channel is on the dial ("Number 30 is already Disney Channel.").
- The launch year is missing or outside 1990–2010, unless the channel is library.
- There are no shows, a show is not in the library, a show is listed twice, or its years are out of range or reversed.
- A show's pretend premiere is outside 1990-01-01..2010-12-31 ("Pick a date from 1990 to 2010.") or after its until year ("This is after the show leaves the channel, so it would never air.").
- The catalog's own cross-file validation fails.
- The one-week invariant smoke test on the same engine fails: every day runs 5 a.m. to 5 a.m. with no gaps or overlaps, and nothing airs before its date, on any channel (M2: library channels included).

Warnings don't block saving: a show with no playable files yet; a show with no air dates and no pretend premiere ("… has no air dates yet, so it won't air. Set a pretend premiere."); a show whose debut comes after its carriage start ("Kim Possible won't air before its 2002 debut.") or after its last carried year ("… debuts Jun 2012, so it won't air here. Set a pretend premiere."); a pretend premiere before the channel is on the dial ("the channel isn't on the dial until 1998. The show starts then.") or later than the real debut ("this is later than its real premiere, so it will air later than it did."). Library channels get the same warnings now (M2).

### Conversion progress: the Media tab (M2 B13)

The `/admin` Media tab polls `GET /admin/media/progress` (above) every 10 s and says "Conversion status isn't available on this server yet" while it returns 404. It shows "Estimating…" until 10 files are done, then averages the last 20 `recent_seconds` times the files left and rounds the ETA to 10 minutes.

## Implemented (M5: viewing reports)

`POST /watch` (`postWatch`, `/api/watch` behind Caddy): the TV reports what was watched, for the weekly station manager (`catalog.md`, M5). LAN-only like everything else. Fire and forget: 204 with no body.

- **Body** (`WatchReport`; unknown fields are refused): `session` (8 to 64 of `A-Za-z0-9_-`, one per program the app plays), `device` (optional label, same characters; the apps send none yet), `channel` (a channel in the effective catalog, else 422), `item` (show or movie id, a slug), `kind` (`episode` or `movie`), `season`, `episode`, `year` (1990 to 2010, or 0 for All Years, whose sessions carry the real date), `offset` (seconds in when tuned in), `seconds` (watched so far, 0 to 6 h), `runtime` (1 s to 6 h), `ended` (`tune_away`, `power_off`, `program_end`, or null while playing).
- **Stored** in `watch_sessions` (migration 0007). The first report of a session inserts it: the server stamps `started_at` as now minus `seconds` (real UTC), works out `sim_date` from that and `year` (the simulated-clock rule), and caps `seconds` at `runtime`. Later reports with the same `session` update it: seconds only grow, never past the runtime or the real time since it started plus 60 s, and `ended` is set once. A session id reused for another channel or program is refused (409).
- **Privacy.** No IP addresses, tokens, URLs or file paths in rows, and nothing logs a report (uvicorn runs without an access log).
- **Never slows tuning.** Reports are written on the schedule cache's own long-lived connection, and SQLite's `data_version` moves only for commits by other connections, so a report every minute never makes the next `/tune` rebuild the schedules (`tests/test_schedule_cache.py`).
